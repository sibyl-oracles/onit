feat(learn): the actuator, and the autonomy ladder that stops lying

Two problems, one cause.

The cause: `lifecycle.py` was 178 lines of policy with zero production
callers.  It decided *whether* a tool had earned an update or an
archive, and nothing ever acted on the decision, so a reader skimming
the tree concluded the tool-lifecycle loop existed.  The other half is
here now.

`actuator.py` is that other half:

* report what the policy decides, whether or not it is enabled to act --
  a deployment should see the policy's mind before letting it change
  anything;
* apply the decisions by *withholding* a tool from the registry -- not
  deleting it.  The handler stays, the tool is still on disk, and the
  next session can have it back;
* restore a withheld tool.

Withholding is reversible by construction, and that is what makes
automating it safe at all: the agent can never permanently destroy
capability.  The archive under `~/.onit/learned/archive/` is the
durable record, and `onit learn --lifecycle` shows it.

Two gates, both of which must open: `learn.lifecycle.enabled` and the
autonomy level at `adapt` or above.  Below that the policy is computed
and reported but nothing is withheld.

The two problems:

1. `_MAX_IMPLEMENTED` was `OBSERVE`, which made the *already-shipped*
   recall and playbook injection paths unreachable -- every one of them
   gates on `autonomy() >= ADAPT`, so committed code could never run.
   The cap moves to `ADAPT`, which is what exists today.  Levels 3 and 4
   are still not built and still cap.

   The cap stays, because the agent must not be able to talk itself into
   a rung it has not earned.  But the cap is now *loud*: `requested_level()`
   and `capped()` tell the request and the grant apart, and `learn report`
   prints "requested evolve (4) -- capped to adapt (2)".  A silent cap is a
   run that believes it is evolving and is not, which is the bug the RFC
   named.

2. `lifecycle.py` had a real bug: `_tool_calls` counted into a fixed key
   instead of the per-tool key, so it raised `TypeError` on the first
   recorded trajectory.  It never surfaced because nothing called it.
   A module with no callers is not tested code, whatever the test file
   says.

Also: `ToolRegistry.withhold()` takes tools out of the offered set and
rebuilds the order list so the survivors keep their relative order, and
`_withhold_archived_tools` is a module-level function rather than a
method, so a caller with only a registry can ask the same question of it.
